# Консоль и `tbot` — руководство оператора

Консоль — локальная веб-страница, с которой видно и запускается всё, что описано в подключённых
папках: стратегии и мониторы. Команда `tbot` делает то же самое из терминала: кнопка и команда —
две дороги к одному и тому же действию. Здесь собрано общее для всех стратегий и мониторов; что
умеет каждая из них и какие у неё страницы — в руководстве её собственного репозитория.

Термины, которые встречаются дальше:

- **Репозиторий-стратегия** — папка с кодом одной или нескольких стратегий или мониторов, их
  настройками и страницами. Консоль в ней не живёт: она приходит как библиотека `tbot-console`,
  которую репозиторий-стратегия ставит себе сам (`uv sync`).
- **Домашняя папка** — репозиторий-стратегия, из которого запущены `tbot` и консоль. Другие
  папки подключаются к ней списком в её файле `config/workspace.json` (§5).
- **Описание** — файл `config/units/<id>.json` в репозитории-стратегии: из каких программ состоит
  стратегия или монитор, как каждую запускать и проверять, на каком порту её служба. `<id>` —
  короткое имя стратегии или монитора; оно же стоит в адресах страниц и в командах `tbot`.
- **Процесс** — одна программа из описания, запущенная на этом компьютере. В командах его называют
  `<id>:<процесс>`, например `console:web` — сама консоль.
- **Служба** — процесс, который считает данные своей стратегии или монитора и по запросу отдаёт их
  консоли. Консоль сама ничего не считает: она показывает то, что прислала служба.
- **Порт** — номер, по которому программа принимает запросы на этом компьютере. Консоль по
  умолчанию слушает порт 8420, служба — порт из своего описания.
- **Торговый процесс** — процесс, который сам отправляет заявки брокеру или бирже (у стратегии в
  описании стоит `places_orders: true`, у процесса — `check: true`). С ним консоль обращается
  осторожнее всего (§1).
- **`.env`** — файл с ключами и паролями в корне репозитория-стратегии. В git он не попадает;
  процессам его передаёт консоль по правилам из §3.

## 1. Запуск, остановка и перезапуск

Все команды — из домашней папки:

```bash
uv run --no-sync tbot up                   # запустить всё, что помечено «поднимать самому»; в конце — адрес консоли, если она поднялась
uv run tbot ps                             # что запущено: процесс, состояние, номер процесса, сколько работает, замечание
uv run tbot start <id>                     # все процессы стратегии или монитора по порядку описания
uv run tbot start <id>:<процесс>           # один процесс
uv run tbot stop <id>                      # все процессы в обратном порядке
uv run tbot restart <id>:<процесс>         # перезапуск: проверка → остановка → запуск
uv run tbot check <id>                     # проверка перед запуском, ничего не запуская
uv run tbot adopt <id>:<процесс>           # взять под присмотр процесс, запущенный не из консоли
uv run tbot output <id>:<процесс> -n 50    # последние 50 строк вывода процесса
uv run tbot json                           # состояние всех процессов для других программ (в формате JSON)
uv run tbot ui-links                       # только для разработки страниц: ссылки на общие файлы консоли (§6)
```

`--no-sync` значит «запустить как есть, не обновляя установленные пакеты». Кнопки «Запустить»,
«Остановить», «Перезапустить» и «Принять» на страницах консоли делают ровно то же, что эти команды,
и для стратегий из подключённых папок тоже. Код выхода `tbot` (число, по которому скрипт узнаёт
итог команды): 0 — сделано, 1 — не получилось, 2 — неверная команда (например, опечатка в имени),
3 — с этим процессом уже идёт другая команда.

**После перезагрузки компьютера** всё, что помечено «поднимать самому» (`autostart` в описании),
поднимает одна команда `uv run --no-sync tbot up` — во всех подключённых папках сразу. Она по
очереди запускает каждый такой процесс, который сейчас не работает, начиная с консоли, и в конце,
если консоль поднялась, печатает её адрес — по умолчанию http://127.0.0.1:8420. Торговые процессы
она не запускает никогда: их запускают только явно, кнопкой «Запустить» или
`uv run tbot start <id>:<процесс>`, посмотрев сначала на состояние. Если в папке, откуда запущена
команда, нет `config/units`, `tbot up` так и скажет: значит, команда запущена не из домашней
папки. Если нужна только консоль — `nohup uv run --no-sync tbot start console` (`nohup` — чтобы
закрытие терминала не прервало команду, пока она ждёт готовности консоли).

**Запуск** идёт в три шага:

1. **Проверка** — только у процессов с `check: true` в описании. Программа запускается с ключом
   `--check` и тем же окружением, которое получит в работе, сообщает, в порядке ли настройки, и
   выходит. Не прошла — запуска нет, а причина видна в строке процесса и в `uv run tbot check <id>`.
2. **Старт** — процесс запускается отдельно и от консоли, и от терминала: закрытие терминала или
   перезапуск консоли его не трогают. Запускается он в папке своего репозитория-стратегии и тем
   Python, который стоит в её `.venv` (папке с установленными библиотеками этого репозитория).
3. **Ожидание готовности** — не дольше `ready.timeout_s` секунд из описания. Готовность бывает трёх
   видов (`ready.kind`):
   - `http` — служба отвечает на свой адрес проверки;
   - `descriptor` — процесс записал свой номер в собственный файл состояния: значит, поднялся и
     работает;
   - `alive` — процесс всё ещё работает через 3 секунды после старта.

   Если процесс за это время упал, команда заканчивается ошибкой и показывает последние 20 строк его
   вывода. Если процесс жив, но готовность так и не подтвердилась, команда считается выполненной, а
   в её итоге об этом сказано.

**Остановка** — процессу посылается мягкий сигнал завершения (SIGTERM — просьба сохранить
состояние и выйти), и `tbot` ждёт до `stop_timeout_s` секунд из описания. Обычный процесс, который
не вышел за это время, завершается принудительно. Торговый процесс принудительно не завершается
никогда: так он оборвался бы без сохранения состояния, а открытые позиции остались бы без
присмотра. Он получает состояние «завис при остановке», и разбираться с ним надо руками.

**Перезапуск** — проверка → остановка → запуск. Проверка идёт до остановки: если настройки плохие,
команда отменяется, а работающий процесс остаётся работать как был.

**Целиком или по одному.** `tbot start <id>` запускает все процессы в порядке описания,
`tbot stop <id>` останавливает их в обратном порядке. С одним процессом одновременно идёт только одна
команда: вторая получит отказ «с этим процессом уже идёт другая операция».

**Подтверждение.** Перед любой командой торговому процессу и самой консоли страница открывает окно
подтверждения. Свой текст для него задают в описании полем `confirm` у процесса; с этим полем окно
появится и у обычного процесса. Остановленную консоль кнопкой не вернуть — только из терминала:
`uv run --no-sync tbot start console`.

**Процесс, запущенный не из консоли** (руками из терминала или старым скриптом), консоль показывает
как «работает без присмотра консоли» и второго такого же не запустит. Кнопка «Принять»
(`uv run tbot adopt <id>:<процесс>`) берёт его под присмотр без перезапуска и без всяких сигналов:
консоль проверяет, что это та самая программа из описания, запущенная из папки своего
репозитория-стратегии (у торгового процесса — ещё и что его номер записан в его файле состояния),
и дальше управляет им как своим. Номер процесса можно указать явно: `--pid N`.

**Сон Mac.** Процесс с полем `keep_awake` в описании на macOS запускается под `caffeinate` —
системной командой, которая не даёт компьютеру уснуть, пока процесс работает (`idle` — не засыпать
от бездействия, `system` — не засыпать совсем, пока компьютер работает от розетки); номер процесса
при этом остаётся его собственным.

**Где что лежит** — в папке того репозитория-стратегии, которому принадлежит процесс:

- `logs/units/<id>.<процесс>.out` — вывод процесса: всё, что он печатает на экран, включая ошибки до
  настройки его собственного лога. При 20 МБ файл сдвигается, хранятся три старых. У принятого
  процесса вывод остаётся там, куда он писал до этого.
- `run/` — служебная папка консоли: состояние каждого процесса (`<id>.<процесс>.json`), последняя
  команда (`<id>.<процесс>.op.json`), блокировка от двух команд сразу (`<id>.<процесс>.lock`) и
  журнал каждой команды по шагам (`run/ops/<номер команды>.log`).

Управление процессами работает на macOS и Linux. На Windows есть два пути: WSL (Linux внутри
Windows) — там всё работает как описано; или без управления процессами — службу стратегии и
консоль запускают руками в двух окнах терминала (службу — её собственной командой из папки
стратегии, консоль — `uv run tbot-web`). Во втором случае консоль покажет процессы, но кнопки будут
недоступны.

## 2. Главная страница и процессы

**Описания.** Каждая стратегия и монитор — отдельный файл `config/units/<id>.json` в своём
репозитории-стратегии. Консоль перечитывает их сама: новое описание появляется на странице
примерно через 15 секунд, удалённое так же исчезает, перезапускать консоль не нужно. Описание с
ошибкой видно красной карточкой с причиной (а в `uv run tbot ps` — строкой «ОШИБКА в …»);
остальные работают. Если у двух описаний одной папки совпал порт, консоль не принимает ни одно из
них (как делят имена и порты разные папки — §5). Файлы, чьё имя начинается с точки (например,
`._demo.json`, который macOS оставляет при копировании, или `.#demo.json`, пока файл открыт в
Emacs), описаниями не считаются и ни на что не влияют.

Что в описании чаще всего меняют:

| Поле | Что это |
|---|---|
| `api.port` | порт службы; порт самой консоли — `console_port` в `config/workspace.json` домашней папки (по умолчанию 8420) |
| `processes.<процесс>.autostart` | поднимать ли процесс по `tbot up`; у торгового процесса — всегда `false` |
| `processes.<процесс>.ready` | как понять, что процесс готов, и сколько секунд ждать (§1) |
| `processes.<процесс>.stop_timeout_s` | сколько секунд ждать мягкой остановки |
| `processes.<процесс>.env_files` | файлы с ключами, которые получает процесс; следующий перекрывает предыдущий. Путь — внутри папки этого репозитория-стратегии: без `..` и без пути от корня диска |
| `processes.<процесс>.env` | переменные окружения процесса — только адреса и пути (§3) |
| `processes.<процесс>.keep_awake` | `idle` или `system` — не давать Mac уснуть (§1) |
| `processes.<процесс>.confirm` | свой текст окна подтверждения |
| `legacy_pages` | старые адреса страниц, которые ведут на эту стратегию |
| `env_files_ignore` | какие переменные из файлов с ключами не получает ни один процесс этой папки (§3) |
| `env_files_only` | какие переменные из файлов с ключами получают процессы этой стратегии; остальные они не видят (§3) |

**Главная страница** (`#/`) — «Стратегии и мониторы»: по карточке на каждую, сгруппированы
«Стратегии», «Мониторы», «Консоль». В карточке — процессы с состоянием словами, номером процесса и
временем работы, кнопки «Запустить» / «Остановить» / «Перезапустить» / «Принять» (только те, что
сейчас имеют смысл), и сводка от службы: заголовок, показатели с подсказками при наведении и до трёх
замечаний. Цветная точка у стратегии в боковой панели: зелёная — всё работает, жёлтая — идёт команда
или что-то не так, красная — упало или не отвечает.

Состояния процесса:

- **работает**;
- **запускается / останавливается / проверяется** — идёт команда;
- **остановлен**;
- **упал** — процесс завершился сам, без команды остановки; причина — в его выводе;
- **завис при остановке** — не вышел за отведённое время; торговый процесс консоль принудительно не
  завершает, разбираться руками (§1);
- **операция прервана** — программа, выполнявшая команду, завершилась посреди неё; проверьте
  состояние и повторите;
- **работает без присмотра консоли** — процесс запущен не из консоли; кнопка «Принять» (§1);
- «(принят консолью)» рядом с состоянием — процесс взят под присмотр кнопкой «Принять».

**Страница «Процессы»** есть у каждой стратегии и монитора (`#/<id>/processes`): те же процессы и
кнопки, а по запросу — последние 200 строк вывода процесса и то, как прошла последняя команда (по
шагам, с ошибкой, если была).

**Адреса страниц:** `#/` — главная, `#/<id>/<страница>` — страницы стратегии или монитора,
`#/<id>/processes` — «Процессы»; `#/<id>` без страницы открывает первую. Старые адреса из поля
`legacy_pages` описания сами переводят на страницу этой стратегии. Незнакомый адрес показывает
заглушку со ссылкой на главную.

**Когда служба не отвечает** — например, поднимается после перезапуска, — сверху страниц её
стратегии висит плашка «Служба … не отвечает» с подсказкой, как её запустить. Когда служба
поднимется, страница продолжит сама.

## 3. Безопасность

**Всё — только на этом компьютере.** Консоль по умолчанию слушает адрес 127.0.0.1: её видно только с
этого компьютера. Службы стратегий и мониторов слушают только этот компьютер всегда; снаружи к ним
попадают лишь через консоль.

**Токен.** `TBOT_WEB_TOKEN` — пароль к консоли. Нужен, только если открывать консоль с другого
компьютера: без токена консоль откажется стартовать на адресе, который виден снаружи. Токен кладут в
`.env` домашней папки. Когда он задан, каждый запрос к консоли должен его нести (заголовок
`Authorization: Bearer <токен>`); страница спрашивает токен один раз и запоминает его в браузере, а
ответ «нет доступа» от любой службы снова открывает форму. В описание токен записать нельзя: имена,
похожие на секрет (кончаются на `TOKEN`, `SECRET`, `PASSWORD`, `PASSWD` или `KEY`), консоль в поле
`env` не принимает.

**Адрес и порт консоли.** Консоль, запущенная через `tbot`, всегда слушает только этот компьютер,
на порту `console_port` из `config/workspace.json` домашней папки (по умолчанию 8420):
`TBOT_WEB_HOST` и `TBOT_WEB_ALLOWED_HOSTS` она из `.env` не берёт, поэтому открыть её наружу правкой
файла с ключами нельзя. Открыть консоль в локальную сеть можно только запустив её руками, без
`tbot`: `uv run tbot-web` из домашней папки. Такая консоль читает `.env` целиком, и там задают
`TBOT_WEB_HOST` — адрес, который слушает консоль (например, `0.0.0.0` — все сетевые адреса
компьютера), `TBOT_WEB_ALLOWED_HOSTS` — дополнительные имена компьютера через запятую (например,
его имя в локальной сети), `TBOT_WEB_PORT` — порт и обязательно `TBOT_WEB_TOKEN`.

**Защита от чужих сайтов.** Консоль отвечает только на адреса этого компьютера (`localhost`,
`127.0.0.1` и другие `127.*`, `[::1]`), на `TBOT_WEB_HOST` и на имена из `TBOT_WEB_ALLOWED_HOSTS`; на
любое другое имя в адресе — отказ, поэтому чужой сайт не доберётся до консоли через подменённое имя.
Любой запрос, который что-то меняет (запуск, остановка, сохранение настроек), принимается только со
служебным заголовком `X-Tbot-Console: 1`, который ставит сама страница консоли: чужая веб-страница в
том же браузере его подделать не может.

**Что получает запущенный процесс.** Его окружение (набор переменных, которые видит программа)
собирается заново, окружение консоли и терминала он не наследует:

1. системные переменные (`PATH`, `HOME`, язык, часовой пояс и ещё несколько);
2. переменные из его файлов с ключами (`env_files`, обычно `.env` его же репозитория-стратегии),
   кроме запрещённых — см. ниже, а если в описании задано `env_files_only` — только перечисленные
   там;
3. поле `env` описания;
4. служебные `TBOT_*`: порт процесса, имя стратегии, папка её репозитория.

Из файлов с ключами процессы никогда не получают:

- `IBKR_ALLOW_LIVE_TRADING` и `IBKR_WRITABLE` — разрешения на торговлю через Interactive Brokers:
  строка в `.env` не может тихо включить заявки;
- `TBOT_WEB_HOST` и `TBOT_WEB_ALLOWED_HOSTS` — адрес консоли не задаётся файлом с ключами;
- всё, что перечислено в `env_files_ignore` любого описания той же папки: начала имён (например,
  `MY_` — все переменные, чьё имя начинается так) и отдельные имена. Так стратегия объявляет, что
  её настройки живут только в её файле конфига и `.env` не может их подменить; такие переменные
  отбрасываются для всех процессов этой папки, а не только для её собственных.

Если в описании задано `env_files_only`, процесс получает из `.env` только перечисленные
переменные; остальные молча пропускаются. Это поле перечисляет начала имён (`prefixes`) и отдельные
имена (`keys`). Консоль так получает из `.env` только свой токен `TBOT_WEB_TOKEN`, а монитор «Демо»
из шаблона (§6) — только переменные на `DEMO_`: ключи и пароли, которые нужны другим программам, в
эти процессы не попадают.

Имена отброшенных переменных записываются в журнал команды (`run/ops/…`). Если какое-то описание не
читается (например, сломан JSON) или его `env_files_ignore` заполнено неверно, не запускается ни один
процесс этой папки, пока файл не исправят: без него неизвестно, что отбрасывать. Процесс под
консолью `.env` сам не перечитывает, так что отброшенное остаётся отброшенным; программа,
запущенная руками, читает `.env` сама — только из той папки, где её запустили, — и переменная, уже
заданная в терминале, главнее файла. Служба стратегии, запущенная руками, берёт из `.env` ровно то
же, что получила бы под консолью; если описания её стратегии нет или в нём ошибка, она сразу
останавливается и называет ошибку, `.env` не читая. Консоль, запущенная руками, читает `.env`
целиком.

В поле `env` описания можно писать только адреса и пути: имена, которые начинаются на `TBOT_` или
кончаются на `_HOST`, `_ALLOWED_HOSTS`, `_CONFIG_PATH`, `_CONFIG_DIR`, `_DATA_DIR`. Ключи и пароли
живут в файлах с ключами, торговые параметры — в конфиге стратегии.

**Чужой код.** Процесс подключённой папки работает от вашего пользователя компьютера: он может
прочитать любые ваши файлы, в том числе `.env` соседних папок, и сам подключиться к брокеру.
Консоль лишь не передаёт ему чужие ключи (файлы с ключами — только из его собственной папки).
Подключайте только папки, чей код вы просмотрели, и обновляйте их только до проверенного состояния
(§5).

**Кэш.** Файлы страницы консоль отдаёт с запретом кэшировать без проверки, поэтому после обновления
кода достаточно обычной перезагрузки страницы.

## 4. Как это устроено

- **Консоль — пульт, а не место, где работают стратегии.** В ней нет кода стратегий и мониторов:
  она не читает ни их журналы, ни биржу. Запрос страницы к `/api/<id>/…` консоль пересылает службе
  этой стратегии на `127.0.0.1:<api.port>`, а порт берёт из описания при каждом запросе. Поэтому
  перезапуск или падение консоли не трогает ни одну стратегию, а перезапуск стратегии — консоль.
- **Страницы стратегии лежат в её репозитории** (`js/units/<имя>/`), и консоль отдаёт их прямо
  оттуда: чтобы изменить страницу, достаточно обновить репозиторий-стратегию и перезагрузить
  страницу в браузере.
- **Каждая команда — отдельная фоновая программа** (`tbot _op`), не зависящая от консоли: если
  консоль перезапустится или упадёт посреди команды, команда доведёт дело до конца. Консоль никого не
  перезапускает сама и при своём старте ничего не запускает.
- **Каждый процесс живёт в своём сеансе**, отдельно от консоли и терминала. Свой процесс консоль
  узнаёт по номеру вместе со временем его старта, поэтому никогда не пошлёт сигнал чужой программе,
  которой система позже выдала тот же номер.
- **Состояние считается при каждом запросе**, а не хранится готовым: консоль, `tbot ps` и `tbot up`
  читают одни и те же файлы в `run/` и список работающих программ, поэтому всегда показывают одно и
  то же.
- **Одна команда на процесс** — это держит файл-блокировка `run/<id>.<процесс>.lock`. Если
  программа, выполнявшая команду, умерла посреди неё, процесс показывается как «операция прервана».

## 5. Подключить новый репо

Консоль видит домашнюю папку и те папки, что перечислены в её файле `config/workspace.json`.
Больше она ничего не ищет: соседние папки сами не подключаются.

1. Скачайте репозиторий-стратегию рядом с домашней папкой и поставьте ему библиотеки:

   ```bash
   cd ~/Documents/Projects
   git clone <адрес репозитория> <папка>
   cd <папка> && uv sync --locked
   ```

   Если в нём есть `.env.example`, скопируйте его в `.env` и впишите свои ключи.
2. В домашней папке создайте или дополните `config/workspace.json` (в git он не попадает):

   ```json
   {"roots": ["../<папка>"], "console_port": 8420}
   ```

   `roots` — список папок, путь считается от домашней; `console_port` — порт консоли, его можно не
   писать.
3. Подождите до 15 секунд: стратегии новой папки появятся на главной странице и в
   `uv run tbot ps`, перезапускать консоль не нужно. Их страницы консоль берёт из `js/units/<имя>/`
   этой папки, процессы запускает в ней и её Python. Уберёте папку из списка — стратегии так же
   исчезнут (работающие процессы при этом не останавливаются: остановите их заранее).

Для работы консоли `tbot ui-links` в подключённой папке не нужен: эта команда только для тех, кто
правит страницы и проверяет их у себя (§6).

**Кто первый, того и имя.** Консоль разбирает папки по порядку: сама консоль, домашняя папка,
затем папки из `roots` в порядке списка. Имя стратегии (и её старые адреса из `legacy_pages`), порт
и имя страниц остаются за тем, кто занял их первым. Описание из более поздней папки с тем же
именем, портом или страницами консоль не принимает и показывает красной карточкой: «имя «…» уже
занято», «порт … уже занят», «интерфейс «…» уже отдаёт другая папка». Имя `console` занято всегда.

**Папка целиком не подключится** (одна красная карточка с причиной), если в ней нет
`config/units`, если она уже в списке или совпадает с домашней, если в ней нет `.venv` или в
`.venv` нет `tbot-console` («выполните там `uv sync`»), или если там стоит `tbot-console` другой
мажорной версии. Мажорная версия — первое число в номере версии (1 в 1.4.2); оно меняется, только
когда старым репозиториям-стратегиям нужны правки, чтобы работать с новой консолью. Сломанный
`config/workspace.json` тоже даёт одну красную карточку; домашняя папка при этом работает.

**Версии и обновления.** Каждый репозиторий-стратегия сам закрепляет, с какой версией консоли он
работает (меткой вроде `v1.0.0` в своём `pyproject.toml`), и переходит на новую своим отдельным
изменением. Консоль запускает процессы папки её собственным Python из `.venv` и сама его никогда
не обновляет, поэтому после `git pull`, который поменял библиотеки папки, выполните в ней
`uv sync`. Держите все подключённые папки на одной мажорной версии консоли: папку, отставшую на
мажорную версию, консоль покажет сломанной, пока её не обновят.

**Безопасность.** Код подключённой папки работает от вашего пользователя (§3, «Чужой код»).
Подтягивайте в неё только проверенный код (`git pull` той ветки, изменения в которую вы сами
приняли); если стратегия читает данные у брокера, включите в программе брокера режим «только
чтение» (в IB Gateway и TWS — «Read-Only API»).

## 6. Написать свой репо

Проще всего начать с копии шаблона — вымышленного монитора «Демо» из этого репозитория,
`tests/fixtures/unit_repo/`. В нём ровно то, что нужно консоли:

```
config/units/demo.json      описание: имя, процессы, порт службы, страницы
src/demo_unit/webapp.py     служба: адрес проверки /api/demo/health и сводка /api/demo/status
js/units/demo/index.js      страницы в консоли (функция createUnitUi) и свой стиль (stylesheet)
js/units/demo/style.css     стиль страниц: каждое правило — под своим классом
pyproject.toml              зависимость tbot-console с меткой версии
.gitignore                  .venv/, run/, logs/, .env, .env.*, config/workspace.json и ссылки от tbot ui-links
```

Правила:

- `tbot-console` подключается как зависимость с меткой версии:
  `tbot-console = { git = "https://github.com/evstifeev-a-s/tbot-console.git", tag = "v1.0.0" }`
  в `[tool.uv.sources]`. Если нужно подключение к Interactive Brokers — `tbot-console[ibkr]`.
- Не объявляйте свои команды с именами `tbot` и `tbot-web` и не кладите файлы в папку
  `tbot_console/`: это имена самой консоли.
- Имя стратегии в описании — от 2 до 31 знака: строчная латиница, цифры и дефис, первой идёт
  буква; оно совпадает с именем файла описания. Порты
  службы выбирайте свободные и не 5432/5433 (порты баз данных).
- Служба строится на `tbot_console.control.service` (`unit_app` и `serve`), сводку для главной
  страницы собирает `tbot_console.control.status`; служба слушает только этот компьютер.
- Страницы: `js/units/<имя>/index.js` экспортирует `createUnitUi(sdk)`; общие помощники консоли
  подключаются относительными путями `../../dom.js`, `../../util.js`, `../../api.js`,
  `../../tooltip.js`. Браузер получает их от консоли, а для проверок в самом репозитории
  (`node --test`, `tsc`, `biome`) команда `uv run tbot ui-links` кладёт в `js/` ссылки на эти
  файлы установленной версии консоли. Эти семь ссылок (`js/api.js`, `js/dom.js`, `js/util.js`,
  `js/tooltip.js`, `js/globals.d.ts`, `js/units/contract.d.ts`, `js/require-tests.mjs`) держите в
  `.gitignore`: в git они не нужны, а файл с таким именем в git команда заменять откажется. На
  Windows без режима разработчика вместо ссылок кладутся копии — после обновления консоли
  выполните `uv run tbot ui-links` снова.
- Проверки описаний и модулей: `tbot_console.testing` (`manifest_problems`, `manifest_modules`,
  `startup_imports`, `imported_modules`) — достаточно одного теста, который прогоняет их по вашей
  папке.
- Торговый процесс: в описании `places_orders: true`, у процесса `check: true` (программа отвечает
  на `--check`), `autostart: false`.
